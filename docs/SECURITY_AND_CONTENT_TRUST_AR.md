# دليل الأمان وجودة المحتوى — LingoNexa 3.0

## الحماية داخل النسخة الحالية

- لا تُخزن كلمات المرور كنص واضح.
- لكل حساب محلي Salt مستقل، وتستخدم كلمات المرور PBKDF2-HMAC-SHA256 بعدد 12,000 دورة.
- تتم مقارنة بصمات كلمات المرور بطريقة ثابتة الزمن لتقليل تسريب التوقيت.
- بعد خمس محاولات دخول خاطئة يفرض التطبيق انتظارًا مؤقتًا.
- الجلسات المحلية تنتهي تلقائيًا، ويختار المستخدم مدتها.
- التحليلات وحفظ التسجيلات الصوتية متوقفان افتراضيًا.
- لا توجد مفاتيح API أو أسرار خدمات اجتماعية داخل المصدر.

## المطلوب قبل النشر التجاري

هذه الحزمة أساس منتج Offline وليست خادم هوية نهائيًا. قبل النشر للعامة يجب تنفيذ:

1. Backend موثوق للمصادقة وتأكيد البريد واستعادة الحساب.
2. تخزين مشفر عبر Android Keystore وApple Keychain ومنظومة آمنة للويب.
3. Access tokens قصيرة العمر وRefresh tokens قابلة للإلغاء.
4. حماية مناسبة للاتصالات الحساسة والتحقق الصارم من TLS.
5. Rate limiting على الخادم، وسجلات تدقيق، وإنذارات للأنشطة المشبوهة.
6. إدارة أسرار خارج المستودع وربط بيئات Development وStaging وProduction.
7. فحص SAST وDependency scanning واختبارات Mobile Application Security.
8. سياسة خصوصية وشروط استخدام وآلية تصدير وحذف الحساب من الخادم.
9. Moderation حقيقية للمجتمع وغرف الصوت والبلاغات وحماية القاصرين.
10. توقيع Android وiOS وحماية مفاتيح التوقيع خارج المصدر.

## منع ظهور المحتوى بطابع آلي

الهدف ليس إخفاء مصدر النص بطريقة مضللة، بل إنتاج محتوى له بصمة تحرير بشرية قابلة للإثبات. كل حزمة تجارية يجب أن تمر بالمراحل التالية:

1. مؤلف منهج يحدد الهدف والمهارة ومستوى CEFR والسياق.
2. متخصص لغوي يراجع القاعدة والمصطلحات والتدرج.
3. مراجع متحدث أصلي يصحح الطبيعية والنبرة واللهجة والبدائل المقبولة.
4. مختص تعليم يراجع قابلية النشاط للقياس والتغذية الراجعة.
5. مسؤول حقوق يوثق مصدر الصوت والصورة والنص ورخصة الاستخدام.
6. ضمان جودة يختبر RTL/LTR والنطق والترجمة وعدم الرجوع للإنجليزية.
7. رقم إصدار وسجل تغييرات وتاريخ مراجعة وأسماء المراجعين المعتمدين.

الحزم التي لم تكمل هذه البوابات تبقى موسومة «حزمة تأسيسية» داخل مركز الثقة، ولا يجوز تسويقها كمنهج راجعه خبراء أو متحدثون أصليون.
